## Gap Analysis (substrate → quest completion)

The static checks above enumerate the substrate gaps. In order of
severity for actually completing Cook's Assistant from a fresh resident:

1. **No quest field in perception** (engine plumbing). The agent
   cannot know it is on a quest, what stage it is at, or which
   ingredient it still needs. Without this, the Brain can only
   re-derive state from the knowledge entry + inventory deltas
   every turn, which is brittle and burns tokens.

2. **No quest goal factory in the Brain planner**. The Brain
   has canonical goals for fishing/cooking/firemaking/etc. but
   nothing for quests. A free-text "complete Cook's Assistant"
   goal has no routing handle.

3. **No quest routine in the Body**. Even with a goal, there is
   no Body workflow that knows how to walk-to-NPC, open dialogue,
   advance through the menu, and select the "yes, I'll help"
   branch. Generic interact talk-to opens the dialogue but the
   Body has no dialogue_choice strategy.

4. **No gateway quest query**. The controller cannot poll quest
   progress to verify or close the loop. Inventory deltas are
   the only handle.

5. **No ingredient-gathering routines**. Body has no windmill
   recipe (climb ladders, fill hopper, operate hopper, descend,
   empty bin with pot), no dairy-cow milking, no chicken-coop
   egg pickup. These are bespoke per-quest sequences.

6. **No dialogue-tree introspection from the agent side**. The
   engine renders dialogue as interface widgets; the agent
   layer sees only resident.busy=true and has to blindly send
   dialogue_continue / dialogue_choice without knowing which
   option corresponds to which line.
